# Architecture and Implementation Status

## Components

- `apps/web/src`: source input, processing/benchmark options, hardware status, persistent job controls, exports and video playback. React and TypeScript, served as static assets by the local API.
- `backend/clipper/api.py`: loopback-session checks, uploads, single-VOD submission, explicit model installation, job control/removal and range-enabled artifact responses. No arbitrary local-file read endpoint.
- `backend/clipper/storage.py`: SQLite WAL jobs, atomic queue claims, a single active lease, heartbeat, interrupted-stage recovery and guarded state transitions.
- `backend/clipper/retention.py`: seven-day terminal-job media retention, original/model preservation, active-source dependency checks and retryable owned-media deletion. Startup/minute sweeps also remove recognizable orphaned run/review/import media after a one-hour modification grace, protecting every registered job/reference, linked paths and unrecognized names. Schema v2 persists an immutable-on-retry expiry deadline; existing terminal jobs are backfilled from their saved updated timestamp.
- `backend/clipper/worker.py`: sequential pipeline orchestration, bounded process execution, cancellation, pause/retry receipts, fingerprints, disk checks and reports. The launcher owns the worker process; the browser does not.
- Analysis-v2 is inside `media.py`: explicit audio/video stream mapping, separate pass logs/timings, CPU baseline or NVDEC hardware decode and early CUDA downscale, validated metadata and cleanCPUfallback. `worker.analyze` reports actualrequested/path/cache and uses a versioned analysis-only receipt rather than globally invalidating speech stages.
- `backend/clipper/speech.py`: explicit model setup and offline inference in a child process. FFmpeg decodes five-minute chunks with two seconds overlap into bounded NumPy audio, bypassing PyAV decoding API incompatibilities. Word timestamps return to source time; duplicate overlap words are suppressed.
- `backend/clipper/media.py`: controlled subprocess arguments, FFprobe, timestamped feature metadata, pause-aware captions capped at three seconds, explicit output-resolution ASScaption geometry, partial foreground zoom over a blurred background, actual NVENC probing and encoder-aware validated exports. SRTremainsanunstyledsidecar. Captionsareappliedaftercomposition, independentofzoom. Auto retries failed NVENC output with CPU; forced mode does not change encoder. Pixel-level tests cover videozoom/backgroundfill, captionglyphheight/aspect/zoom-invariance and expiry.
- `backend/clipper/analysis.py`: conservative activity heuristic. Sparse 1 fps visual analysis and local audio baseline changes generate candidates, context windows and overlap suppression. Spoken windows use punctuation/pause boundaries and skip candidates without a suitable boundary; source edges and silent action are preserved. A relative score is not a viral probability.
- `backend/clipper/rerank.py`: pinned publisher GGUF/runtime installation and bounded Qwen transcript assessment. CPU server is temporary, offline and authenticated on loopback; a single child stage owns its lifetime. Responses reference supplied candidate/evidence IDs, never new timestamps. The worker validates ratings, blends semantic/activity scores only when meaningfully differentiated, caches by model/prompt/inputs and otherwise retains the baseline.
- `backend/clipper/download.py`: restricted YouTube/Twitch VOD adapter backed by yt-dlp. No cookies, playlists, live input or cloud inference.
- `backend/clipper/cli.py`: doctor, explicit model installation, benchmark and combined service/worker startup.

## Transcript Health and Ranking Guards

`speech.transcript_health` summarizes bounded Whisper word probabilities, repeated trigrams and retained segment diagnostics. `speech.transcribe` saves segment start/end and avg_logprob/compression_ratio/no_speech_prob without another inference pass. Clip and benchmark reports expose the summary; UI status is diagnostic, not an accuracy score. The English-only model cannot independently verify spoken language, so language remains explicitly unverified.

Activity selection keeps peaks when local speech is unreliable rather than rejecting them for missing sentence boundaries. Usable speech retains the existing boundary rules. The reranker excludes unreliable transcript contexts but keeps their activity scores, along with silent candidates. Near-flat or mostly near-perfect ratings retain the original activity selection with visible no_separation/saturated_scores status. Guard version and per-window diagnostics participate in the rerank receipt key; old speech receipts can be reused with missing metrics explicitly represented. No cloud, new model, GPU allocation or automatic caption suppression is introduced. Detailed thresholds and limitations: [local-reranker.md](local-reranker.md).

## Scene-Aware Distinct Selection

Analysis v3 appends FFmpeg scdet(threshold12) and scene-time metadata after the existing1fps/160px sampling graph. CUDA/NVDEC ordering remains fps->scale_cuda->hwdownload; there is no extra full-source decode, model or dependency. CPU and GPU paths share scene metadata; partial scene output is removed before CPU fallback. Only analysis receipts advance to3, retaining existing speech/probe caches.

Clip edges prefer a cut within3seconds while retaining the activity moment and15-90second bounds, then usable speech can extend to sentence-safe edges. Cuts are one-second hints, not exact shot segmentation. The ranked shortlist rejects shared footage over0.25seconds and long usable-confidence dialogue with>=20normalizedtokens and>=0.90ordered SequenceMatcher similarity. Short/uncertain/silent content is not dialogue-deduplicated. This is not semantic event recognition or visual replay detection.

Reports record analysis scene method/settings/count, selection policy version2/thresholds/maximum/exported/aligned counts, per-export scene_adjusted and non-AI stages.select timing. Renderer/ClipPlan6 lifts the unchanged97.2px font by48px at1080x1920 (bottom margin9%); receipts invalidate old caption positioning without rewriting completed exports.

## Data and Recovery

`.data/jobs.sqlite3` persists work; `.data/worker.json` reports a recent worker heartbeat. Per-run media, logs and receipts are under `.data/runs/<id>`. A stage receipt's key covers source content, options and pipeline version. Renderer v5 additionally keys completed exports on the full ClipPlan, including boundaries, zoom, requested encoder and renderer version, invalidating older small-caption renders. A cached export also needs `encoding.json` so reports retain actual encoder/fallback and caption canvas/font size/uniform scale. It is not yet a shared cross-run artifact cache. The browser exposes foreground zoom, not a full editor; all speech/analysis/encoding requests use GPU-preferred Auto. Forced hardware policies remain CLI/API diagnostics.

Encoder selection is separate from ASR device selection. Each uncached rendering job probes an actual1080x1920 NVENC encode once; CPU mode skips the probe, Auto records fallback, forced NVENC fails if unavailable. If an Auto NVENC render or validation fails, it retries once through libx264 and retains that decision for later clips. Cancellation remains a separate control-flow exception and never triggers fallback. Metadata records actual encoder, probe/render durations, bytes and CPU decode/filter stages. No concurrent Whisper/Qwen/encoding stages are introduced. Public prerequisites and fallback limitations are in [gpu-setup.md](gpu-setup.md).

Analysis decoder is a separate thirdpolicy, not implied by speechdevice or encoder. The GPUgraph samples hardwareframereferences before scaling/downloading; filtering1fps only after full-frameGPUtransfer was measured and rejected as ineffective. Unsupported/invalidGPUfeatures never silently replace the CPUbaseline. Slight feature-value drift is expected across resamplers; source-time coverage and rankedwindows are compared explicitly. The savedAV1 comparison matchedall1118timestamps and top-tenwindows, but that is not a generalquality guarantee.

Atomic JSON updates use unique temporary files and bounded retries for transient Windows replace locks. Advisory heartbeat PermissionErrors are nonfatal; SQLite leases, not this status file, control ownership. Required receipt/report write failures are still surfaced. This fixes a reported WinError 5 during a real YouTube run without requiring elevation or disabled antivirus. Refreshing only rereads state; it is not a processing-repair operation.

Jobs use `queued`, `running`, `paused`, `cancelled`, `failed`, `succeeded`, and `expired` during pending media deletion. A stale owner cannot finalize a job claimed by another worker. Process exit releases inference state before final rendering. Pausing an active stage terminates its subprocess; resume redoes that incomplete stage. Recovery relies on a 30-second lease after abrupt shutdown. Stage execution has a finite wall-time bound. Transient processing errors are not retried indefinitely; users can retry explicitly. Downloader retries are bounded separately.

Retention cleanup atomically marks expired terminal jobs and clears exported references before removing their owned directories/imports. The row is forgotten only when cleanup succeeds. File-lock failures remain retryable and cannot be requeued as processing work. Active/queued/paused work is excluded; media needed by another active file-source job is retained until released. Cleanup runs on API/worker startup and approximately every minute while processing or idle. Artifact access checks the deadline independently and returns 410 at expiry. No physical deletion can happen while all app processes are stopped. Models, external originals and separately downloaded exports are not subject to this policy.

Keep the development service on loopback. Browser operations require a same-origin local token. Artifact routes use registered job/export IDs and a fixed filename allowlist. Subprocesses use argument arrays without a shell. Downloads and imports are bounded, but this is not a multi-tenant hostile-media sandbox. Automated CDN redirect isolation, complete log redaction and OS-level media sandboxing remain future hardening work.

## Cross-Machine Testing

The CLI creates allowlisted Windows test ZIPs with optional pinned tools/model assets and a size/SHA256 manifest. Source/tests/docs/builtUI are transferable; recordings, database/queue state, virtual environments, node_modules and logs are not. Standalone standard-library verification runs before setup. Setup creates a fresh environment using the tested Python3.12x64 baseline and treats doctor failure as a failure, not success. See [testing-other-windows.md](testing-other-windows.md).

CLI benchmarks refuse live workers/non-idle queues and claim only the requested job. Reports contain path-free hardware/software/model fingerprints, source/options/backend/lock identity, per-attempt encode/inspect/decode-validation timings and best-effort standby clock diagnostics. Optional --keep-awake is active-job-scoped and restores the thread's previous state; no global power policy changes. Explicit --output saves a report outside managed retention without overwriting. This is not a fully offline/signed installer or proof of behavior on another physical machine.
